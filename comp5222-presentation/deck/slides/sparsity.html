Caveat in our current code

The GAT stores a padded N×N tensor with an edge mask, so memory is still O(N²): batches are capped at B·N² ≤ 8.4M. Switching to PyG GATConv with edge lists, as the proposal planned, would turn the sparsity into real savings.

Measured on 400 test chains, w = 2, k = 8

Each residue has two local neighbours on each side plus its top-8 non-local partners, and the union adds a few more, so on average a residue has about 16 neighbours. Across 400 test chains only 7.5 percent of residue pairs are edges. One honest caveat: our implementation still uses a dense padded tensor with a mask, so the sparsity limits what attention sees but does not yet save memory. Moving to an edge-list GAT, as planned, would fix that.
